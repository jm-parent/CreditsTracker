# Rust + Tauri Rewrite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite Credits Dashboard so its non-graphical core is pure Rust and its window is hosted by Tauri, with every Rust unit proven against a recording of the current TypeScript behavior.

**Architecture:** One rust-anything crate per core unit under `rust/<unit>/`, each holding pure Rust in `src/port.rs`. A Tauri app in `src-tauri/` calls those crates through commands that mirror the current IPC channels. The existing React renderer stays, behind a transport shim. A headless TypeScript reference in `reference/` is the recorded original, and a clap front door in `rust/app/` replays the whole app.

**Tech Stack:** Rust (cargo 1.99.1, MSVC toolchain), rust-anything 3.3.0, Tauri 2 with its Windows bundler and updater plugin, rusqlite, prost, an HTTP server crate, TypeScript/Node 24 for the reference, vitest for the existing renderer tests.

**Spec:** [docs/superpowers/specs/2026-11-23-rust-tauri-rewrite-design.md](../specs/2026-11-23-rust-tauri-rewrite-design.md)

## Global Constraints

- Windows only. Build with the MSVC toolchain. The rust-anything install docs require Visual Studio Build Tools with the C++ workload.
- Electron 44 and the existing vitest suite stay green until Task 19.
- No runtime bridge between Rust and Node in product code. napi bindings generated by `rust-anything bridge` are test scaffolding only.
- `~/.copilot/session-store.db` is opened read-only, and nothing writes to it.
- No real usage data, prompts, or transcripts committed. Fixtures are synthetic.
- No usage data, prompts, responses, or transcripts sent off the machine.
- Logs at `%APPDATA%\credits-tracker\logs\app.log`, rotated at 2 MB. Tauri identifier `credits-tracker`.
- Commits use Conventional Commits and end with `Co-authored-by: Copilot App <223556219+Copilot@users.noreply.github.com>`.

## Review Focus

1. Missing or locked `session-store.db`: the core returns a not-found error that the UI can show, nothing crashes, and it is logged. Owning task: 11.
2. Non-ASCII project names and summaries (accents, emoji, CJK) survive queries, HTML escaping, and file names. Owning tasks: 11, 13, 12.
3. Malformed or truncated OTLP bodies, and pending spans past 16 MiB, are rejected and counted while the receiver keeps serving. Owning tasks: 5, 9.
4. Empty date ranges and empty databases produce empty states, with no NaN and no division by zero in "% of total". Owning tasks: 11, 12.
5. A log file past 2 MB rotates, and a missing log directory is created on first write. Owning task: 3.

Each line gets its test in the owning task's step list.
