# Spec Kit Existing Features Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Integrate GitHub Spec Kit for Copilot and publish living, evidence-based specifications for all thirteen existing Credits Dashboard capabilities.

**Architecture:** Use the official Specify CLI to add Spec Kit's project configuration and Copilot skill files without touching application code or npm dependencies. Store the project constitution and baseline functional specs alongside the standard `specs/` index, and document the contributor workflow in the existing English developer documentation.

**Tech Stack:** GitHub Spec Kit (`specify-cli`), GitHub Copilot skills, Markdown, existing Electron/React/TypeScript repository and Vitest tests.

## Global Constraints

- Spec Kit is a development-time tool; do not add it to `package.json` or application runtime code.
- Keep each baseline feature contract at `specs/NNN-feature-name/spec.md`; treat it as the living source of truth.
- Use English to match the existing README and developer guide.
- Preserve all existing application behavior and unrelated worktree modifications, including the existing `.github/copilot-instructions.md` changes.
- Do not migrate or rewrite historical files under `docs/superpowers/`.
- Derive requirements from the current implementation, existing documentation, and tests; do not invent product behavior.
- Create `plan.md` and `tasks.md` only for future implementation work, not as retroactive artifacts for existing features.
